# Docksmith — UI/UX 설계

**톤앤매너**: Stripe, Linear, Notion, Cursor, Claude 같은 미니멀 SaaS 스타일. 화려한 장식 없이, 여백을 넉넉히 쓰고, 화면마다 "지금 눌러야 할 버튼 하나"가 명확하게 보이게 만든다. 물류 실무자는 바쁘고 IT에 익숙하지 않을 수도 있으므로 — 화면에 설명이 많은 것보다 **버튼이 적고 명확한 것**이 더 중요하다.

---

## 0. 디자인 시스템 기초

| 항목 | 값 | 이유 |
|---|---|---|
| 폰트 | Inter (본문), 시스템 폰트 fallback | 가독성 좋고 무료, Stripe/Linear도 유사 계열 사용 |
| 색상 | 배경 흰색/아주 밝은 회색, 텍스트는 짙은 회색(순검정 X), 포인트 컬러 1개(예: 남색 계열) | 색이 많으면 "지금 뭘 눌러야 하지?"가 헷갈림. 포인트 컬러는 오직 주요 액션 버튼에만 사용 |
| 여백 | 넉넉하게(컴포넌트 사이 최소 24px) | 서류 작업 자체가 빡빡하고 복잡한 일이라, 도구는 반대로 "숨 쉴 틈"을 줘야 함 |
| 컴포넌트 라이브러리 | shadcn/ui + Tailwind | 커스터마이징 쉽고, 1인 개발자가 디자이너 없이도 일관된 결과물을 냄 |
| 다크모드 | MVP 제외, V1에서 검토 | 리소스 우선순위상 핵심 기능에 집중 |

## 1. 랜딩 페이지 (SEO용, 예: `/commercial-invoice-generator`)

**목적**: "지금 이 문제로 검색해서 들어온 사람"이 30초 안에 "이게 내 문제를 푸는 도구구나"를 이해하고 무료로 시작하게 만든다.

**레이아웃** (위→아래 한 줄로 쭉 내려가는 단일 컬럼 구조)
1. 헤드라인: "FedEx Commercial Invoice, 30초에 500장 만들기" 같은 구체적 문장 (일반론적 "문서를 자동화하세요" 금지 — PRD 차별화 포인트와 직결)
2. Before/After 비주얼: 왼쪽 "엑셀 붙여넣기 반복" 스크린샷 느낌 vs 오른쪽 "3초 완료" 느낌의 간단한 일러스트
3. 주요 CTA 버튼 **"무료로 시작하기"** (포인트 컬러, 화면에서 제일 눈에 띄는 요소)
4. 실제 동작 미리보기(짧은 GIF 또는 정적 스크린샷 3장: 업로드→클릭→다운로드)
5. 하단에 보조 CTA 반복

**컴포넌트**: Hero 섹션, 3단계 스텝 카드, 단일 CTA 버튼(반복 배치), 짧은 FAQ 아코디언

**버튼**: 주요 버튼 1개만("무료로 시작하기") — 페이지 전체에서 같은 문구로 반복. 보조 버튼(로그인)은 헤더 우측 상단에 작게.

**UX 이유**: 검색해서 들어온 사람은 둘러볼 시간이 없다. 선택지를 줄이는 게 전환율을 올린다 — 버튼이 여러 개면 사람들은 아무것도 안 누른다.

---

## 2. 가입 / 로그인

**목적**: 최소 클릭으로 다음 화면(온보딩)에 도달.

**레이아웃**: 중앙 카드 하나, 이메일/비밀번호 입력 2개 + "Google로 계속하기" 버튼 하나.

**버튼**: 주요 - "Google로 계속하기"(가장 위, 가장 크게. 클릭 한 번으로 끝나서 이탈이 적음), 보조 - 이메일 가입.

**UX 이유**: 회원가입 단계에서 이탈이 제일 많다. 선택할 게 적어야 한다.

---

## 3. 대시보드 (로그인 후 첫 화면)

**목적**: "내가 뭘 만들었고, 다음에 뭘 해야 하는지"를 한눈에.

**레이아웃**
- 상단: "새 템플릿 만들기" 큰 버튼 (화면에서 가장 눈에 띄는 요소 — 신규 사용자든 재방문자든 여기부터 시작)
- 중단: 내 템플릿 카드 그리드 (템플릿 썸네일 + 이름 + "생성하기" 버튼) — 재방문자는 여기서 바로 CSV만 올리면 끝
- 하단: 최근 생성 이력 (날짜, 건수, 다운로드 다시 받기)
- 사이드바(좌측, 얇게): 대시보드 / 설정·과금

**컴포넌트**: 템플릿 카드, 빈 상태(Empty State — 템플릿이 없을 때 "첫 템플릿을 만들어보세요" 안내), 생성 이력 리스트

**버튼**: 주요 - "새 템플릿 만들기"(상단), 각 템플릿 카드 위 보조 버튼 - "생성하기"

**UX 이유**: 신규 사용자와 재사용자의 목적이 다르다(신규=만들기, 재방문=바로 생성). 두 경로 모두 이 화면 하나에서 즉시 시작할 수 있어야 재사용 플로우(PRD 3.2)의 "30초 이내" 목표가 지켜진다.

## 4. 템플릿 매핑 스튜디오 (핵심 화면 — 가장 신경 써야 할 부분)

**목적**: PDF 위에서 "여기에 값이 들어간다"를 클릭으로 표시하고 저장한다.

**레이아웃** (좌우 2분할)
- 좌측(넓게, 화면의 70%): PDF 페이지 렌더링, 사용자가 마우스로 사각형을 그리면 그 자리에 필드 박스가 생김. 이미 지정된 필드는 옆에 라벨 태그가 붙어 보임(예: "invoice_no").
- 우측(사이드 패널, 30%): 선택된 필드의 속성(이름/타입: 텍스트·숫자·날짜·금액), 전체 필드 목록, "저장" 버튼

**컴포넌트**: PDF 캔버스 뷰어, 드래그 가능한 필드 박스(리사이즈 핸들 포함), 필드 속성 폼, 필드 목록 리스트(클릭하면 해당 필드로 스크롤/하이라이트)

**버튼**: 주요 - "저장하고 계속" (우측 패널 하단, 다음 단계인 5번 화면으로 이동), 보조 - "필드 삭제"(각 필드 박스에 hover 시 작은 X 버튼)

**UX 이유**: 이 화면이 어렵게 느껴지면 사용자는 여기서 이탈한다. 그래서:
- 처음 진입 시 "이 서류에서 바뀌는 부분을 클릭하고 드래그해서 표시하세요"라는 짧은 안내 오버레이를 한 번만 보여준다.
- 필드를 지정할 때마다 우측 목록에 즉시 추가되어 "내가 지금까지 몇 개 표시했는지" 진행 상황이 눈에 보여야 한다(작업의 끝이 보이면 계속할 동기가 생긴다).
- 색상은 필드 박스에만 포인트 컬러를 써서, 서류 위의 원래 텍스트와 확실히 구분되게 한다.

## 5. 데이터 업로드 & 생성 실행

**목적**: CSV를 올리고, 컬럼이 필드에 잘 연결됐는지 확인한 뒤 "생성" 한 번으로 끝낸다.

**레이아웃** (위→아래 3단계가 순서대로 나타남, 이전 단계 완료 전엔 다음 단계 흐리게 비활성화)
1. CSV/Excel 드래그&드롭 업로드 영역
2. 컬럼-필드 매칭 테이블: 왼쪽에 CSV 컬럼명, 오른쪽에 자동 매칭된 필드(딕셔너리로 자동 연결됨), 안 맞은 건 드롭다운으로 수동 선택. 상단에 첫 3줄 미리보기 테이블.
3. "생성하기" 큰 버튼 → 클릭 시 진행률 바(브라우저에서 처리 중이라는 표시, "1,204 / 2,000건 처리 중")

**컴포넌트**: 드롭존, 매칭 테이블, 미리보기 테이블, 진행률 바(Progress Bar), 오류 배지(빨간 숫자로 "3건 오류" 표시)

**버튼**: 주요 - "생성하기"(모든 필수 필드가 매칭된 후에만 활성화됨), 보조 - "다시 업로드"

**UX 이유**: 사람이 가장 불안해하는 순간이 "이거 누르면 뭐가 만들어지는 거지?"이다. 그래서 실행 전에 반드시 미리보기(3줄)를 보여줘서 "이런 서류가 이렇게 만들어지는구나"를 확신시킨 뒤에만 큰 버튼을 활성화한다.

## 6. 생성 결과 화면

**목적**: 결과를 확인하고 다운로드한다. 실패한 게 있으면 무엇이 문제인지 바로 알려준다.

**레이아웃**
- 중앙에 큰 숫자로 결과 요약: "1,997건 완료 · 3건 오류"
- 주요 버튼: "ZIP 다운로드" (가장 크고 눈에 띄게, 화면 중앙)
- 오류가 있으면 그 아래 오류 목록(어느 행, 어떤 필드가 비어있었는지)

**컴포넌트**: 결과 요약 카드, 다운로드 버튼, 오류 테이블(펼치기/접기)

**버튼**: 주요 - "ZIP 다운로드", 보조 - "오류 행만 다시 시도"

**UX 이유**: 실패가 있어도 전체를 막지 않는다 — 성공한 것부터 먼저 받게 하고, 실패는 따로 고쳐서 재시도하게 한다. "하나라도 틀리면 처음부터 다시" 방식은 대량 작업 도구에서 최악의 경험이다.

---

## 7. 설정 / 과금

**목적**: 지금 어떤 플랜인지, 얼마나 썼는지 확인하고 업그레이드한다.

**레이아웃**: 상단에 현재 플랜 카드(이번 달 사용량 게이지 바 포함), 하단에 플랜 비교 표(Free/Starter/Pro/Team), 우측 상단에 "결제 정보 관리"(Stripe Customer Portal로 이동)

**버튼**: 주요 - 각 플랜 카드의 "업그레이드" 버튼, 보조 - "결제 정보 관리"

**UX 이유**: 사용량 게이지가 한도에 가까워질수록(예: 80% 이상) 카드 색이 경고색으로 바뀌게 해서, 한도 초과로 작업이 막히기 전에 자연스럽게 업그레이드를 유도한다.

## 화면 간 이동 흐름 요약

```
가입/로그인 → 대시보드 → [새 템플릿] → 매핑 스튜디오 → [저장] →
데이터 업로드 & 생성 실행 → 생성 결과 → (대시보드로 복귀)

재방문 시: 대시보드 → [기존 템플릿 "생성하기"] → 데이터 업로드 & 생성 실행 → 생성 결과
```

매핑 스튜디오는 **처음 한 번만** 거치고, 그 다음부터는 항상 "대시보드 → 업로드 → 결과" 3단계로 끝난다는 것이 이 설계의 핵심이다 — 이게 PRD에서 정의한 재사용 가치(재방문 시 30초 이내 완료)를 화면 구조로 구현한 것이다.
